1) Introduction
The purpose of this document is to define the functional and technical requirements of the
AI-powered eLearning and Interview Platform, consisting of:
● A B2B institutional platform for colleges and universities
● A B2C AI Interview platform for individual users

===== PAGE 3 =====
The system enables: ● AI-driven course generation from academic content ● AI-powered tutoring and assessments ● Voice-based AI interview simulation with evaluation and reporting This document serves as a reference for product, engineering, QA, and stakeholders to ensure aligned development and delivery. 2. Purpose The objective of this platform is to: ● Transform static academic content into interactive AI-driven learning experiences ● Provide personalized, on-demand tutoring ● Enable automated interview preparation with real-time evaluation ● Offer data-driven insights for students, faculty, and institutions Key Outcomes: ● Improve student learning efficiency ● Increase placement readiness ● Provide institutions with actionable analytics ● Create a scalable AI-first education ecosystem 3. Overall Description 3.1 Product Perspective The system is a multi-tenant SaaS platform consisting of: B2B Platform: ● Super Admin Portal (Platform Owner) ● College Admin / Faculty Portal ● Student Portal B2C Platform: ● Student Portal (Standalone Interview System) ● Super Admin Portal (Global control)

Core Systems: ● AI Content Generation Engine (RAG-based) ● AI Interview Engine (voice-based) ● AI Tutor Engine (contextual QnA) ● Scoring & Report Engine ● Notification System 3.2 Operating Environment Frontend: ● Web-based application (Desktop-first) ● Built using ReactJS ● Supported browsers: Chrome, Edge, Safari (latest versions) Backend: ● Python FastAPI (REST APIs) ● Asynchronous processing supported Infrastructure: ● Cloud: AWS / GCP ● Storage: AWS S3 (media, content, recordings) ● Database: PostgreSQL ● Vector DB: Pinecone / Weaviate AI Stack: ● LLM APIs: OpenAI / Anthropic / Google ● STT: Whisper / Deepgram ● TTS: ElevenLabs / Deepgram ● Real-time: LiveKit / Vapi 3.3 Design & Implementation Constraints ● System must be multi-tenant with strict data isolation ● All AI responses must comply with guardrails (safe, contextual outputs) ● Voice-based systems must maintain low latency (<3 seconds response cycle) ● Avatar systems must not degrade performance ● Platform must support horizontal scaling

Objective Build a system that automatically converts educational PDFs (e.g., engineering textbooks) into short animated educational videos. The system should: • Accept PDF uploads from an admin. • Extract and structure educational content. • Divide long chapters into smaller segments (e.g., 5‑minute sections). • Generate visual explanations (diagrams, animations, slides). • Generate voice narration. • Render the final educational video automatically. 2.
